Основные документы для действующей системы:

1. [OPERATIONS.md — инструкция дежурного](OPERATIONS.md): проверить сайт, найти ведущего, определить неисправную службу, прочитать очереди и копии.
2. [RECOVERY.md — восстановление и развёртывание](RECOVERY.md): перезапуск, возврат узла из резервной копии, подготовка новой машины, восстановление ub22 и SQL.
3. [STATUS_2026-10-19.md — зафиксированное состояние](STATUS_2026-10-19.md): принятый релиз, выполненные проверки, открытые замечания.

Установленный программный релиз на дату передачи: `5bb19267248cb14f97edbdb3717bf94829c436bd`. После изменения только документации `main` может иметь другой SHA без изменения runtime.

## Инструменты

| Инструмент | Применение |
|---|---|
| `diagnose_cluster.py` | Чтение ролей, версий, готовности служб и резервов |
| `diagnose_fault.py` | Расширенная диагностика узла с очисткой известных секретов |
| `diagnose_sql_locks.py` | Чтение SQL-сеансов и блокировок; результат зависит от SQL-прав |
| `audit_wallboard_live.py` | Проверка Grafana, запросов панелей и backend на ub22 |
| `release_update.py` | Подготовка и установка точного релиза; восстановление по журналу незавершённой установки |
| `recover_bus_rollout.py` | Управляемая установка: held-резервы, release, ведущий последним |
| `update_visual_wallboard.py` | Отдельное обновление двух экранов и коллектора на ub22 |
| `verify_factory_acceptance.py` | Проверка рабочих endpoints и прогресса обработки реального прохода |

Диагностика не требует запуска новой установки. Команды и ожидаемые результаты приведены в инструкции дежурного.
