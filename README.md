# КПП «Периметр»

Учёт проходов барабанов: RFID, камеры, СКУД, сопоставление со складом и Web-интерфейс. Рабочим узлом управляет Guardian; два остальных узла служат резервами. Ведущего определяет SQL-аренда с fencing protocol 2.

**Состояние на 19 октября 2026:** развёртывание передано в сопровождение с открытым замечанием по периодическим тайм-аутам SQL-зеркала. Автообновление из `main` подтверждено на трёх узлах. Установленный программный релиз: `5bb19267248cb14f97edbdb3717bf94829c436bd`. Подробности и границы проверки — в [карточке состояния](deploy/ha/STATUS_2026-10-19.md).

## Из чего состоит обработка

| Служба | Назначение | Локальная готовность на ведущем |
|---|---|---|
| RfidReader | Приём меток и доставка чтений в SQL | `127.0.0.1:18101/health/ready` |
| RusGuardSync | Доставка СКУД | `127.0.0.1:18102/health/ready` |
| Yolo | Камеры и видеособытия | `127.0.0.1:18103/health/ready` |
| Aggregator | Сопоставление чтений, видео, СКУД, склада | `127.0.0.1:18104/health/ready` |
| WebDashboard | Сайт рабочего узла | `127.0.0.1:18105/health/ready` |

Guardian: TCP 18200; Web рабочего узла: TCP 5050; постоянный Gateway на ub22: TCP 5051. Службы принимают производственные записи только при действующей SQL-аренде. Общие SQL, RFID-считыватель и камеры остаются общими зависимостями всех узлов.

## Изменение кода

Автообновление следит за `origin/main`. Проверка выполняется примерно раз в 60 секунд; тесты, подготовка и приёмка занимают дополнительное время. Новый программный релиз сначала проверяется и устанавливается на резервах, затем выполняется управляемая передача роли. Изменения только в Markdown не требуют перезапуска runtime; SHA документации в Git может быть новее установленного релиза.

Не выполнять `git pull` внутри работающего дерева. Использовать отдельную ветку, проверки CI и штатный механизм обновления. Изменения схемы БД, зависимостей и моделей требуют отдельного развёртывания. Перенос кода сам по себе не обновляет Grafana на ub22.

## Данные и восстановление

Git хранит исходный код и инструкции. Для восстановления нужны также частные конфигурации, пароли, SQL backup, состояние узлов, очереди и настройки инфраструктуры. Их состав и порядок возврата описаны в [RECOVERY.md](deploy/ha/RECOVERY.md).

При действующем HA не запускать `RUN_RFID_KPP_FINAL.cmd` параллельно Guardian. Не удалять SQLite-очереди и `release.json`, не сбрасывать SQL-флаги ошибок вручную.
