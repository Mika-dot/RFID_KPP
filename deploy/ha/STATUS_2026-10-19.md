## Решение о передаче

Развёртывание и подтверждённый рабочий контур переданы в сопровождение с открытым замечанием по периодической задержке SQL-зеркал. Это не акт устранения всех неисправностей и не подтверждение полного резервного копирования SQL.

Основание — журналы команд оператора на Physical, Perimetr, Comparator и ub22, а также результаты GitHub Actions. Прямого непрерывного доступа к производственной сети из среды разработки не было.

## Открытое замечание: зеркало событий

Ранее повторялись `mirror_sync_blocked`, поток `events`, SQL native code 1222. Синхронизация частично продолжается, но успешный отдельный SELECT не снимает замечание.

Последний общий снимок, присланный около 12:24 МСК:

| Узел | Роль | Состояние копии | Возраст самой старой части |
|---|---|---|---|
| Physical | Резерв | ОШИБКА | около 703 секунд |
| Perimetr | Ведущий | ОШИБКА | около 445 секунд |
| Comparator | Резерв | ГОТОВА | менее секунды |

Отдельная проверка Comparator: все шесть потоков `events, warehouse, tasks, rfid, video, skud` догнаны, возраст около 12 секунд; повторные чтения успешны за 1–24 мс. Рабочие и справочные данные в этой проверке читаются с SQL Server `SRV-SQL4`, база `1CTgSend`.

На момент передачи причина периодических блокировок не устранена. 90-секундная выборка SQL-сеансов не застала блокировку; полнота видимости сеансов у использованного SQL-подключения отдельно не установлена. Правильная проверка серверного разрешения: `HAS_PERMS_BY_NAME(NULL, NULL, 'VIEW SERVER STATE')`. Прежний вариант с классом `'SERVER'` вернул NULL и не подтверждает права.

Состояние `СВЕЖИЕ` в таблице очередей относится к телеметрии узла. Для готовности копии отдельно нужны `cache_state=ГОТОВА`, догнанные шесть потоков и допустимый возраст. `cache_days=93` — политика хранения, не доказательство накопления полного 93-дневного архива. Одинаковое число строк не подтверждает одинаковое содержимое.

## Границы передачи

- Реальный контрольный проход выбранного барабана по всей цепочке, правильность направления, видео и сверка с 1С в этом сеансе не выполнены.
- Физическое отключение питания/сети и недельное наблюдение не выполнены.
- Наличие пригодной для восстановления полной копии SQL и комплектов резервных копий машин не подтверждено. Их подготовка входит в эксплуатационное обеспечение.
- Успешные запросы панелей не подтверждают смысловую правильность статусов всех 19 проектов, включая «Сокол ЕЛЛ-60».
- Статус ведущего меняется при реальном отказе. Использовать текущую схему/диагностику, не считать epoch 9619 или роль Perimetr вечными настройками.
- `pending=true` на пассивном узле означает, что его новый runtime ещё не прошёл испытание в роли ведущего. `prepared=true` подтверждает подготовку резерва, но не заменяет такой проверки.
